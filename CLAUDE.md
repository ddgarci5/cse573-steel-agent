## 1. What we are building

An engineering decision-support agent that takes a natural-language steel member design problem, converts it to a typed
`DesignCase`, retrieves the governing AISC 360-22 provisions, calls deterministic Python design tools, searches candidate
W-shapes, verifies every required limit state, and produces an auditable report for a human engineer.
It does NOT replace a licensed engineer.

Research questions:
- RQ1: How accurately can an open-weight LLM (with and without RAG and LoRA) extract a complete DesignCase from natural language?
- RQ2: Does deterministic tool use plus independent verification reduce calculation errors and unsafe recommendations vs. an LLM-only approach?
- RQ3: Can the full agent recommend sections whose validity and weight match the deterministic reference (System A)?

## 2. Non-negotiable rules

1. **The LLM never computes structural numbers.** It interprets, plans, selects tools, and explains. All capacities come from `steelagent/` functions.
2. **No section is ever recommended unless every required check passes in deterministic code.** ML and the LLM may only propose or rank.
3. **No fabricated results.** Every number in a slide, README, or report must come from a script in this repo with a saved output file.
4. **Avoid circular validation.** The solver is validated against AISC-published values (Dataset C) before it generates any training labels. Dataset C is never used for training.
5. **Copyright.** AISC Manual tables, AISC Design Examples, the sponsor's teaching modules, and textbooks live in `references/` (gitignored). Store only problem parameters and published answers in our own JSON. Never commit or redistribute AISC text.
6. **Units:** U.S. customary throughout (kips, in., ksi, kip-ft). Lengths in ft at the interface, in. inside calculations.
7. **Reproducibility:** fixed seeds, pinned package versions, every experiment writes JSON/CSV to `results/` with a timestamp and git hash.
8. Ask before broadening scope beyond the MVP below.

## 4. MVP scope (core) vs. stretch

**Core MVP**
- ANSI/AISC 360-22, 16th Ed. Manual resources, **LRFD only**, ASTM A992 (Fy = 50, Fu = 65, E = 29,000 ksi), rolled **W-shapes**.
- Inputs are given design demands (Pu, Mu, Vu, optional service load + deflection limit), not raw building loads.
- Tension: D2 yielding; D2 rupture only when An and U are supplied (otherwise the agent asks for them).
- Compression: E3 flexural buckling about both axes; E7 slender elements. E4 torsional buckling assumed not to govern (Lcz ≤ Lcy).
- Flexure: F2 yielding + LTB (all three zones, Cb), F3 flange local buckling; G2.1 shear; L/360-type deflection check when service data given.
- Exhaustive lightest-section search; ML shortlist; LLM extraction; RAG over provisions; verifier; Streamlit report.

**Stretch (only if core is done)**
ASD; load combinations and structural analysis; Chapter H combined forces; F4/F5 noncompact/slender webs; block shear and connections;
HSS/angles/channels; knowledge-graph or GNN components beyond the small provision/limit-state graph.

## 7. DesignCase schema (Pydantic; typed, with units)

```json
{
  "problem_id": "str",
  "member_type": "tension | compression | flexure",
  "design_method": "LRFD",
  "material": {"grade": "ASTM A992", "Fy_ksi": 50, "Fu_ksi": 65, "E_ksi": 29000},
  "demands": {"Pu_kip": null, "Mu_kipft": null, "Vu_kip": null},
  "geometry": {"L_ft": null, "Lb_ft": null, "Lcx_ft": null, "Lcy_ft": null, "Kx": null, "Ky": null, "Cb": null},
  "net_section": {"An_in2": null, "U": null},
  "serviceability": {"w_live_kipft": null, "deflection_limit": "L/360"},
  "constraints": {"nominal_depth_in": null, "max_depth_in": null, "section": null},
  "missing_fields": ["..."],
  "provenance": {"source_spans": {}, "retrieved_provisions": [], "rule_ids": []}
}
```
An executable "required checks" map (member type → limit states → provisions → required inputs) drives both the tool plan and the verifier's completeness rule.
It doubles as the small provision/limit-state knowledge graph shown in the presentation.

## 8. Experimental systems

- **System A**: deterministic solver + exhaustive search (reference).
- **System B**: classical ML. Decision Tree, then Random Forest and gradient boosting (XGBoost if installable, else sklearn HistGradientBoosting). Tasks: case–section pass/fail; regression of lightest passing weight → shortlist top-k → System A re-checks. Report feature importance (e.g., Lb/ry).
- **System C**: LLM-only (no tools, no retrieval) answers the problem end to end.
- **System D**: full agent. Ablations: base model, +RAG/tools, +LoRA.
Evaluate on Dataset C (engineering claims) and the Dataset B held-out split (larger-sample statistics). Repeat LLM runs 3× at temperature 0.

**Metrics.**
- Extraction: field-level P/R/F1, exact-match, missing-field detection.
- Correctness: pass/fail accuracy, governing-limit-state accuracy, capacity and utilization error.
- Safety: **unsafe-acceptance rate** (target 0 for System D), hallucinated provisions.
- Selection: valid-recommendation rate, exact match to System A, weight gap.
- ML: F1, top-k recall (target ≥95% at k=10), solver calls saved.
- Agent: task success, tool-call validity, retries, abstentions, latency, provision retrieval precision@k.

## 9. Agent architecture (LangGraph)

Parse → Validate (schema, units, plausible ranges; missing fields → ask the user) → Retrieve (AISC 360-22 provision index with section-number metadata)
→ Shortlist (DB filter + System B ranker) → Calculate (deterministic tools) → Verify (completeness vs. required-checks map, recompute governing check,
every number/provision in the draft must match a tool output or retrieved passage; ≤3 bounded retries, then abstain) → Report.
Persistent state: shapes registry, provision index, verified-case cache. Request-scoped state: DesignCase, candidates, tool results, retry counters.

**Models.** Benchmark 2–3 open-weight instruct models in the 7–8B range via Ollama (current Qwen-family instruct as primary, plus one Llama or Gemma).
Confirm the newest releases at build time. Optional larger hosted references via ASU Voyager.
LoRA/QLoRA with Hugging Face PEFT on ASU Sol or Colab; target only extraction, tool selection, and report structure, never numbers.

**Demo.** Streamlit. Input such as "Select an ASTM A992 W-shape column for Pu = 420 kips, Lx = 14 ft, Ly = 10 ft, Kx = Ky = 1.0".
Show: interpreted inputs → required checks → candidate table (section, capacity, utilization, pass/fail) → recommendation → controlling limit state
→ verification status → provision citations → calculation summary.
