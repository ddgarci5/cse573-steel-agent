# Agentic AI for Design of Steel Structural Members

Course project for CSE 573 (Semantic Web Mining), Arizona State University, Fall 2026 (Group 13, Project 18).

The goal is an engineering **decision-support** agent: it takes a natural-language steel member design problem, turns it into a typed design case,
retrieves the governing AISC 360-22 provisions, calls deterministic Python design tools, searches candidate W-shapes, verifies every required limit state,
and writes an auditable report for a human engineer. **It does not replace a licensed engineer.**

Two rules shape the whole repository:
1. **The language model never computes structural numbers.** It interprets, plans and explains. Every capacity comes from the deterministic code in `steelagent/`, and no section is recommended unless every required check passes there.
2. **No result is typed in by hand.** Every number in this README comes from a script in this repo and a saved file under `results/`.

### Results at a glance
- **Solver vs published values.** Agreement is within AISC's three-significant-figure rounding on every Manual-table check (above). The solver does not implement E4, F4/F5, block shear, connections or Chapter H (see "Limitations").
- **System B** (synthetic data; HistGB shortlist of 10 sections, then System A re-check): the true lightest passing weight is in the shortlist for 1.0000 of in-range test cases (compression and flexure). Out-of-range (longer lengths): 1.0000 compression, 0.9985 flexure. Mean solver calls per case 1.35 (compression) and 1.22 (flexure) vs 132.3 and 126.2 for System A stopping at the first pass. The Decision Tree is weaker out of range on flexure (recall@10 0.9115). These scores are on an easy synthetic task, so treat them as an upper bound, not expected real-world accuracy. The classifier alone is not safe (false-pass rate 0.12% to 0.16% in range); recommendations are only returned after System A re-checks them.
- **System C (no tools).** With a 4,000-token output cap, gemma4-31b-it answers all 27 strength runs and 15 of 27 are within 1% of AISC; qwen38-27b answers 17 of 27 and 7 of 27 are within 1%. Selection matches the AISC section in 8 of 12 (Gemma) and 3 of 12 (Qwen) runs, and some answers are sections that do not exist or fail a System A check. Outputs differ between repeats even at temperature 0. Full table, per-problem errors and caveats: `results/SESSION_SUMMARY.md`.

## Setup
Python 3.12 or newer (developed and pinned on 3.14.7). Windows is the tested platform.
```
uv venv --python 3.14 .venv
uv pip install --python .venv/Scripts/python -r requirements.txt     # on macOS/Linux: .venv/bin/python
```
Activate the environment (`.venv\Scripts\activate`) and use `python` in the commands below.

External pieces, none of which are in the repository:
- **AISC Shapes Database v16.0** (free Excel file): see "Data sources". Save it as `steelagent/data/aisc-shapes-database-v16_0.xlsx` (underscore in the version).
- **poppler `pdftotext`** (only for re-parsing the Manual tables; the xpdf build bundled with Git for Windows is rejected on purpose): `scoop install poppler`.
- **Ollama** (only for the local System C run): `scoop install ollama`, then `ollama pull qwen3.5:9b`.
- **ASU Voyager credentials** (only for the Voyager System C runs): create a `.env` file at the repo root with `VOYAGER_BASE_URL=...` and `VOYAGER_API_KEY=...`. It is gitignored. These are ASU-provided and are not part of this repository.

Notes:
- LLM outputs from Voyager are not deterministic even at temperature 0, so a rerun will not reproduce the saved System C numbers exactly. The saved raw outputs in `results/system_c_pilot_*/raw/` are what the reported numbers were computed from. Re-scoring them is deterministic.
- The System C scorer (`eval/system_c_pilot.py`) is frozen; every run's `summary.json` records its sha256 so you can check which version scored it.
- `steelagent/validation/rescore_shipped_csv.py` needs the per-case CSVs that `validate_*.py` write into `steelagent/validation/` when `STEELAGENT_OUT` is unset; those CSVs hold AISC table values and are gitignored.

## Limitations
- **Solver scope.** Not implemented: E4 torsional / flexural-torsional buckling (assumed not to govern), F4/F5 noncompact and slender webs (no shape in the database needs them), block shear and connections, Chapter H combined forces, ASD, stiffened webs, other shapes and steel grades. Deflection is checked only as a minimum Ix. Effective lengths and Cb are inputs.
- **Validation breadth.** The E7 slender-element path is checked against the W14 slender shapes in the Manual excerpt and the Design Examples only, while 101 of the 289 shapes have slender webs in compression.
- **System B** is trained and tested on synthetic data whose demands are built from a section's own capacity; it says little about real design problems.
- **System C** is a pilot on 13 problems with 3 repeats per model; counts are small and outputs vary between repeats. Many answers depend on the model recalling section properties from memory.
- No license has been chosen yet.

## How this was built
Development used an AI coding assistant (Claude Code) working in this repository under the rules in `CLAUDE.md`. All reported results are produced by scripts in this repo and saved in `results/` with timestamps; each experiment folder records the package versions, and the git hash and whether the working tree was clean (`meta.json`). The assistant does not compute any design value that appears in a result: those come from `steelagent/`.
